Correr liquidación del período

Aguinaldo

1/12 de lo cobrado en el período. Antes hay que tener los meses corridos y emitidos (si no, no encuentra base).

Salario vacacional — Uruguay

Líquido de los días de licencia, sobre el último recibo mensual emitido de cada empleado. Los días reales surgen de la antigüedad; acá se ingresan a mano.

Despido / liquidación final — Uruguay (piloto)

De un empleado a una fecha de egreso: indemnización + aguinaldo proporcional + licencia no gozada + salario vacacional. Necesita su último recibo mensual emitido. No lo da de baja: eso es aparte.

Novedades del período

Insumos variables por empleado (días, horas, unidades, comisiones) y ausentismo (faltas, tardanzas, horas a descontar). El reloj también puede empujar estos datos por API (pestaña Integración).

Ausentismo y horas

Cargá faltas, llegadas tarde, horas a descontar y horas extra de un empleado en un período. Faltas, tardanzas y horas a descontar restan del sueldo; las horas extra suman, con el recargo del país. Todo se aplica al correr la liquidación. Un sistema de relojes puede empujar lo mismo por API (pestaña Integración).

Dejá un campo vacío para no tocarlo; poné 0 para borrarlo. Estos descuentos asumen mes completo: para un mensual usá esto o "días trabajados", no ambos.

Retenciones

Retenciones al salario: judiciales (embargos, pensión) y voluntarias (préstamos, etc.). Se aplican solas en la liquidación mensual, sobre el líquido, por orden de prioridad. Los préstamos se amortizan al emitir.

Integración

Conectá un sistema de relojes/fichaje para que empuje la asistencia por API, sin carga manual. Los datos que llegan (días trabajados, faltas, tardanzas, horas a descontar) entran como novedades del período y alimentan el motor igual que si los cargaras a mano.

Tokens de servicio

Un token identifica al sistema externo y le da acceso solo a esta empresa. Se muestra completo una sola vez; guardalo en un lugar seguro.

Cómo enviar la asistencia

El sistema externo hace un POST con el token en el header. Puede identificar a cada empleado por su documento o por relacion_id. Reenviar el mismo período reemplaza los valores (no duplica).

POST /integracion/asistencia
Authorization: Bearer png_xxxxxxxx...
Content-Type: application/json

{
  "periodo": "2025-03",
  "items": [
    { "documento": "12345678", "dias_trabajados": 21 },
    { "documento": "98765432", "faltas": 2, "tardanza_min": 35 },
    { "relacion_id": "uuid-...", "horas_extra": 8, "horas_descuento": 4 }
  ]
}

Nota: para un mismo empleado usá dias_trabajados o faltas, no ambos (se duplicaría el descuento). Las horas extra se liquidan con el recargo del país (configurable como dato).

Remuneración variable

Definí los esquemas de incentivo de tu empresa: sueldo variable, comisiones y bonos. Un plan agrupa objetivos (cuantitativos o cualitativos) y una curva que traduce cumplimiento en pago. Acá armás el catálogo, lo asignás a la gente y cargás los resultados por período. El motor no calcula el variable: al cerrar el período, el monto ya resuelto entra como un concepto de liquidación.

Conceptos de liquidación

Conceptos que el liquidador puede sumar o restar en una liquidación: premios, gratificaciones, viáticos, reintegros, descuentos. Acá definís el catálogo; en el paso siguiente se podrán aplicar a cada empleado y período. El motor sigue calculando aportes e IRPF sobre lo gravado.

Asientos contables

El asiento de sueldos sale de los recibos ya emitidos: definí a qué cuenta de tu plan contable y de qué lado (debe o haber) va cada parte, y descargás el asiento listo para tu software contable. El motor no recalcula nada; sólo se agrupan los montos.

Asistente
